# 第5段训练流程与安全分支

更新日期：2026-09-15。按《新的游戏计划》的第五段实施，参考《游戏使用流程》和《三阶段康复游戏系统设计交接文档 S1-S3 修订版》的准备、暂停、异常、安全停止和描述性总结要求。9月15日增加“语音引导＋数据门禁”：拍照后语音引导回位，短时断流非阻塞自动恢复，持续15秒才升级全屏异常。

## 本轮范围

本轮以游戏框架为主：对当前选择的一种动作、一个照片目标创建独立训练会话，不改变人物骨骼驱动、四元数转换、根节点补偿及三种动作的测量/判定算法。保留第四段浅蹲游戏联调规则。

安全停止在本版指停止游戏对焦/取景更新、保持计时、快门与目标推进；不是硬件急停，也没有额外停止人物底层实时驱动。人物动作测量仍由客户结合设备调整。界面明确说明四个下肢传感器不能自动识别躯干代偿、疼痛或真实跌倒；不生成诊断、疗效、临床正确率或自动进阶/退阶结论。

本轮没有扩展为完整 S1 三动作自动排课、S2 组合、S3 序列、跨次训练进展、云同步或临床复核权限系统。当前一次总结的范围是 `single_action_photo_session`；照片目标不是完整动作次数，不能作为临床质量评价。

## 如何启动

打开现有 `RehabPhotoGame` 场景并播放，无需手动挂载新组件。

1. 在准备页或底部“设备设置”连接设备。启动检查明确限定 06、07、08、09，不要求内部九槽中的 01～05。
2. 依次点击三个整行确认按钮：环境无障碍且椅子/所需支撑稳固；四传感器位置正确并固定；本人已经考虑疼痛与疲劳、本次可以开始。按钮用“点击确认/已确认”和底色共同显示状态，不依赖方框字体。这是本人确认，不是系统识别身体状态。
3. 保持站姿，点击下一步按钮。若 06～09 未就绪，按钮会打开设备设置并说明缺少条件；已有数据但现有标定条件未满足时，也会进入设备设置。就绪后按钮调用客户已有的标定/开始驱动接口，不重新设计标定算法。若已完成则显示“已就绪”；佩戴或位置改变应从设备设置先重置再标定。
4. 选择坐姿伸膝、坐站或浅蹲，以及照片目标。只有上述确认、四传感器新鲜数据、有效测量和标定/驱动状态均满足时，才能点击“开始训练”。
5. 开始后仍需按原动作状态机确认准备姿势：伸膝需坐稳垂腿，坐站需坐稳，浅蹲需站稳。站姿标定不等于动作准备已经完成。

开始按钮不再隐式替用户触发标定，并会逐项显示当前缺少的是本人确认、06～09 数据、站姿标定/动捕还是流程配置。底部设备、帮助和安全停止入口位于模态层上方，准备、暂停及异常页面中仍可访问；未开始/已结束时安全停止按钮不可重复操作。

## 流程分支

| 分支 | 游戏行为 | 恢复/结束 |
| --- | --- | --- |
| 主动暂停、帮助/休息、窗口失焦 | 保留已拍照片、最后画面和角度反馈；停止新的游戏判定；暂停时长单独统计 | 数据连续有效后由用户点击继续，再从动作准备开始；原保持不补算 |
| 拍照后回位准备 | 保留拍摄成功反馈并播放回位语音；游戏流程进入 `ReturnPreparation`，禁止再次拍照 | 由现有动作状态机确认已经回到准备姿势后自动进入下一次，不新增动作角度规则 |
| 当前动作所需传感器短时无效 | 进入 `SignalRecovery`，立即冻结保持、进度和拍照；底部显示恢复状态并且每段波动只播报一次，不显示全屏异常 | 至少两个不同的新样本连续有效达到0.7秒后自动恢复，不要求点击“继续”；旧保持时间不补算 |
| 异常持续达到15秒 | 升级为 `SensorError`，暂停动作运行时并显示原全屏异常页 | 数据恢复稳定后允许人工确认继续；安全停止和结束训练仍可用，不把异常解释为动作失败 |
| 主动重置或检测到重标定版本变化 | 中断本次动作并要求重新准备 | 等待重新连接/标定和有效数据后，主动继续 |
| 不适/安全停止 | 立即结束当前游戏会话、取消快门闪光和音效；记录安全原因与最后有效测量 | 进入 `review_required`，不能直接继续旧会话；提示休息与适当复核 |
| 达到照片目标 | 保存描述性总结与照片计数 | 返回设置或休息；重新训练须重新确认清单 |
| 主动结束、退出游戏/停止播放 | 保存现有数据与具体结束原因 | 不作惩罚，不将未完成照片解释为临床失败 |

训练开始要求四个传感器全部有效；训练中沿用动作所需掩码：左伸膝使用 06+07，右伸膝使用 08+09，坐站/浅蹲使用四个。非训练腿断流不阻止当前单腿游戏，但顶部仍显示对应设备状态异常。切换训练腿会先暂停，继续前检查新训练腿并重新准备。

恢复确认需要至少两个不同的有效新样本，且持续达到配置的确认时间；收到旧样本不能积累恢复确认。短时波动恢复后自动继续；只有已经升级为全屏异常或由用户主动暂停时才保留人工继续按钮。

拍照后按模式播报“缓慢放下小腿 / 缓慢坐回 / 缓慢站直”。浅蹲回到现有 `Preparing` 状态且数据有效后，播报“准备完成，请开始下一次浅蹲”。语音只描述游戏流程，不说“动作正确”、不判断疼痛、代偿或跌倒。

注意：游戏流程的“冻结”不更改底层人物驱动。最后一张照片拍摄后当前会话即总结，不把尚未验证的返回过程计成完整正确动作。三种动作的旧动作诊断日志仍独立保留。

## 可配置参数

Unity Project 中选择 `Assets/Resources/RehabPhotoGame/TrainingFlowConfig.asset`。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `config_version` | `stage5-game-flow-v2` | 本次流程配置版本 |
| `recovery_confirm_seconds` | 0.7 秒 | 异常/暂停后数据恢复确认时间，不是人体动作角度稳定时间 |
| `sensor_error_timeout_seconds` | 15 秒 | 从游戏检测到所需数据无效起计算的非阻塞恢复宽限；到时才升级全屏异常，不替代原传感器新鲜度门限 |

每次开始训练复制流程配置，进行中的会话不因资产修改而改变。推荐停止播放后修改并保存再测；打包版本需要重新构建。无效配置阻止开始。

动作角度、保持目标和传感器新鲜度仍由原动作运行时配置负责，本文件不覆盖。浅蹲参数仍在 `ShallowSquatGameTuning.asset`。不通过延长传感器新鲜度来掩盖断流。

## 语音资源

独立 `TrainingVoiceGuide` 优先加载 `Assets/Resources/RehabPhotoGame/Voice/` 中的预录音频；未提供录音时，Windows 编辑器/打包程序使用系统中文TTS后备。批处理测试不启动TTS进程。正式交付建议放入以下同名 `.wav` 或 Unity 支持的音频文件（资源引用不带扩展名）：

- `photo_complete_squat`、`photo_complete_sit_to_stand`、`photo_complete_knee_extension`
- `ready_squat`、`ready_sit_to_stand`、`ready_knee_extension`
- `signal_recovering`、`signal_recovered`、`signal_error`

语音按流程事件触发，不逐帧重复；同一提示有5秒防重复间隔。坐姿伸膝动作层已有回位语音，因此正式界面不会在拍照后叠加第二条同类语音。

## 本地记录与结果字段

编辑器中：项目根目录 `Logs/TrainingSessions/`。

打包运行时：`Application.persistentDataPath/Logs/TrainingSessions/`，使用可写用户数据目录，避免安装目录不可写。原有 motion diagnostic JSONL 路径不变。

每次训练生成独立全局 `session_id`：

- `<session_id>.events.jsonl`：开始、拍摄、回位完成、暂停、短时信号波动、自动恢复、全屏异常升级、继续、结束/安全停止，以及可选的训练后本人反馈。每条带独立 `event_id`、UTC 时间、本地时区偏移、原因、版本和训练 ID。
- `<session_id>.summary.json`：单次结果，使用临时文件完成写入并刷新后原子重命名。同一 ID 重复保存相同内容不会增加记录，不允许覆盖不同结果。
- 同时将流程事件和总结以 `training_flow_` 前缀镜像到原有诊断 JSONL，便于和运动数据对齐。独立结果存储不受旧动捕日志保存开关影响。

| 字段 | 含义/缺失规则 |
| --- | --- |
| `session_id / started_at_utc / timestamp_utc / timezone_offset` | 会话标识、开始/结束 UTC 时间和本地偏移 |
| `stage / scope / action_type` | 当前为 S1 单动作摄影会话；动作码 `sit_knee_extend / sit_to_stand / squat` |
| `planned_photos / captured_photos / photo_completion_rate` | 照片目标、实拍数量及比率；不是完整动作次数或临床正确率 |
| `duration_seconds` | 会话总经过时长，以单调运行时钟统计 |
| `active_seconds / paused_seconds / sensor_error_seconds` | 游戏活动、主动暂停、异常冻结时长；活动时长含动作准备，不含暂停/冻结 |
| `pause_count / sensor_error_count` | 主动暂停（含求助/失焦）次数和异常段次数 |
| `preflight_confirmed` | 三项本人确认已完成，不代表身体状态经设备验证 |
| `termination_reason` | `target_completed / user_end / sensor_timeout / user_safety_stop / application_exit / storage_error` |
| `safety_stop / review_status` | 安全停止、需复核、数据异常无效会话或仅描述性结果 |
| `has_last_valid_measurement / last_valid_measurement` | 是否有最后有效下肢测量及其内容；没有数据时不能把零值当真实角度 |
| `rule_version / config_version / config_snapshot / app_version` | 游戏流程规则、配置快照与应用版本；开始事件也保存流程配置快照 |
| `quality_assessment / clinical_pass` | 固定为 `not_evaluated`，本轮不做临床质量/达标计算 |
| `sensor_confidence` | `not_available`，不把连通状态伪装成经过验证的置信度 |
| `pain_assessment` | 仅本人状态确认与可选感受反馈，不采集数字量表、不自动识别疼痛 |

动作级配置仍以各动作原有启动诊断事件为准，流程配置快照不是动作算法配置的副本。没有用户账户，因此本轮不伪造 `user_id` 或用户内训练序号，不实现跨用户历史归属。

训练后“感觉尚可 / 疲劳，想休息 / 疼痛或不适”作为附加事件写入同一训练 ID 的事件日志，不覆盖已经保存的原始总结。任何不适反馈事件标记 `review_required`；查看记录时必须同时读总结和事件，不能仅依据总结中的结束时状态忽略后续本人反馈。未填写不等于无疼痛；多次填写按事件顺序保留，不适提示不会被随后点击“感觉尚可”清除。

写盘失败时停止游戏并显示重试保存，不显示已经保存成功。临时事件保留在当前进程内等待重试；重试成功前不能从总结返回设置。强行结束进程、断电或磁盘损坏时无法保证未落盘内容恢复；本轮没有后台同步或崩溃恢复管理器。数据只保存在本机，不自动上传。

## 客户复测清单

1. 缺少任一 06～09、未标定或未完成任一本人确认时，不能开始；补齐后能进入所选动作准备。不要求 01～05。
2. 三种模式各完成至少一张照片，验证原玩法仍可使用；保持/返回动作阈值沿用上一版。
3. 保持期间暂停 5 秒：画面和保持冻结、照片数不增加；恢复后从准备开始，不能马上补拍。切换到其他窗口也应暂停。
4. 完成一张浅蹲照片：应听到“拍照完成，请缓慢站直并站稳”；尚未站回时不能产生第二张；站回并由原动作状态机确认准备后，应听到“准备完成，请开始下一次浅蹲”。
5. 断开当前动作必需的一个传感器并在15秒内恢复：立即停止计时和拍照，底部显示“正在自动恢复”，只播报一次信号波动，不出现全屏弹窗；连续恢复约0.7～1秒后自动继续，不要求点击。单腿伸膝的非训练腿断流不阻止当前腿。
6. 持续断流达到15秒：此时才显示全屏异常；恢复后按钮可人工继续，原照片数保留，异常不显示成动作失败。
7. 分别在保持中、短时恢复中、暂停中、全屏异常中点击安全停止：立即停止游戏推进；不能直接继续旧会话；原照片保留且记录 `review_required`。只测试按钮，不要求真人制造疼痛或失衡。
8. 主动结束/完成目标后检查总结：照片、目标、时长分类和原因正确；点击本人反馈后能在同 ID 事件日志找到记录。
9. 从总结返回设置，再开始必须重新确认清单，创建新训练 ID。旧结果不被覆盖。
10. 原动捕日志开关关闭时，独立 `TrainingSessions` 记录仍能保存。常规退出/停止播放也应有明确结束原因。

反馈请附：完整录屏、对应原始 motion diagnostic JSONL、`TrainingSessions` 中同一 ID 的两份文件，以及使用的流程配置截图。注明测试模式、发生时间点、当时点击的按钮/断开的设备、实际与预期表现。无需为了测试提交个人身份或医疗资料。

## 自动验证

纯逻辑和 Unity 回归入口已扩展：`Tools/Check-Stage1.ps1` 与菜单 `Tools → Rehab Photo Game → Run Stage 5 Regression Tests`。覆盖前置确认、暂停计时、旧样本恢复、超时、安全优先级、重标定、配置快照、时钟回拨、独立会话、持久化、模态入口和画面冻结。日志见 `Logs/Stage5-validation.log`；自动界面渲染在 `Logs/Stage5Review/`。这些检查不能替代客户四传感器实机验收，也不是临床安全认证。

本轮结果：60 项纯逻辑测试通过；Unity 第1～5段共 78 项回归检查通过，退出码 0。已检查准备、回位门禁、短时非阻塞恢复、15秒异常升级、暂停、安全停止及完成总结。17 个动作测量/驱动及三种动作相关源文件保持不变。
