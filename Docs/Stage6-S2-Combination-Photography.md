# 第六段 S2 组合摄影与客户验收

本段优先推进游戏框架，只读取现有伸膝、坐站、浅蹲快照中的分相、保持完成与返回计数。未修改骨骼驱动、四元数转换、三个动作判定器、动作参数或根节点补偿。模式切换只调用现有训练模式启停接口。

## 入口与计划

打开 `Assets/City park/Scenes/RehabPhotoGame.unity`，进入播放模式。在训练前准备卡中选择 **S2 组合摄影**，完成原有四传感器 06～09、本人确认和站姿标定门禁，然后开始。

准备卡提供 **仅组合 A / 仅组合 B / A+B 连续** 三种训练内容，默认保留 A+B 连续。仅 A 完成后直接总结，不再强制进入 B；仅 B 从站立准备开始，不要求先完成 A。联调可单独调整当前所选内容的组数；A+B 时同时调整两部分，`1+1组` 适合首次连续验证。配置入口为 `Assets/Resources/RehabPhotoGame/S2CombinationConfig.asset`，A/B 各 1～5 组，默认停顿提醒 5 秒。配置在训练开始时复制，不更改动作角度或保持时间。

本原型没有实现阶段解锁、临床进阶、授权身份系统或完整处方评估。S2 是人工选择的联调入口。组数和动作目标用于现场测试，不是对患者训练量的临床建议。

## 正常闭环

组合 A：

1. 坐稳准备，伸膝逐渐完成远景对焦，按原动作要求保持。
2. 对焦完成后等待缓慢放下小腿；此时不播放摄影快门，不增加组合照片数。
3. 只有伸膝状态机确认放下完成，才启用坐站模式。双脚着地，先由原状态机确认稳定坐姿，再缓慢站起。
4. 坐站状态机完成站稳保持，播放一次快门，收集一张“远景对焦 + 高处景物”双联 JPG。
5. A 还有下一组时，等待原坐站状态机确认稳定坐回，再开始下一组对焦。最后一组 A 完成后不额外要求坐回；选择“仅组合 A”时直接总结，选择“A+B 连续”时保持站立进入 B 的站立准备。

组合 B：

1. 先由原浅蹲状态机确认稳定站姿，不从坐姿直接拍摄。
2. 缓慢浅蹲，固定取景画框内低处素材滚动；进入原目标并满足保持要求时播放一次快门。
3. 此时显示“低处已拍，请缓慢站回”，但不增加完整组合照片数。
4. 原浅蹲状态机确认稳定站回后，才收集“站立取景 + 浅蹲低处取景”双联 JPG，增加一张完整组合照片。
5. 下一组重新确认站立准备；最后一组站回后显示训练总结。

双联照片由现有摄影素材组成，不是患者照片或人物动作截图。B 双联采用同一低处素材的不同取景窗口；完成返回只是生成完整组合照片的条件，不代表额外拍摄了一次人物照片。

## 调整、暂停与断流

- 未完成当前步骤时停下等待，不自动跳到下一动作；不因等待时间较长判错。A 的动作衔接等待超过默认 5 秒，仅提醒一次“不用着急，可以按自己的节奏继续”。
- “重新本组”清除当前未完成步骤，回到该组合的坐姿或站立准备，不删除之前收集的照片。
- “调整 / 下一组”把当前组记录为主动跳过，不生成照片；下一组重新准备。A 已拍高处但仍在坐回时，这个入口暂不可用，因为该组已经完成。
- 原动作参考被清除、动作会话版本变化或切腿时，当前未完成组合回退并重新准备。普通幅度不足、保持中断或浅蹲过深仍沿用原动作层的调整流程，不自行重算动作。
- 暂停、帮助/休息和长时异常恢复后重新准备当前未完成组合；已收集照片保留，不补算旧保持时间。
- 短时断流沿用第五段自动恢复门禁，冻结游戏进度、对焦/滚动和拍照。四传感器连续有效达到原配置确认时间后自动恢复。门禁期间发生的快门/返回边沿不会在恢复后补记，必要时重新准备本组。
- 持续断流 15 秒才升级原全屏异常窗口。安全停止始终可见，并禁止继续旧会话。数据异常、主动求助和安全停止不记为动作错误或自动退阶。

由于本轮禁止新增动作识别，仅保证游戏步骤门禁不接受未完成的前置步骤。对真实身体是否漏做、借力或坐下的辨别，仍取决于客户现有动作测量和状态机，不宣称已经可靠区分。

## 记录位置与字段

编辑器：工程根目录 `Logs/TrainingSessions`。Windows EXE：`%USERPROFILE%/AppData/LocalLow/DefaultCompany/KOA/Logs/TrainingSessions`（以该构建公司名、产品名为准）。

每次训练包含：

- `<session_id>.events.jsonl`：第五段安全/门禁事件与 S2 步骤、提醒、重试、跳过、低处快门、组合完成事件。
- `<session_id>.summary.json`：`stage=S2`、`scope=ordered_combination_photo_session`，以及 `combinations.training_plan`（`a_only / b_only / a_then_b`）、完成组、已处理组、跳过组、重新准备次数、规则/配置版本和照片列表。
- `<session_id>_<photo_id>.jpg`：每个完整组合一张双联照片，1296×360；照片列表的 `image_file` 对应此文件，`image_status=saved` 表示保存成功。

完整组合照片与原动捕诊断日志通过会话 ID、事件时间关联。低处快门事件 `combination_low_shutter` 不等于完整 B 组照片。`resolved_a/b` 包括完成与主动跳过，`completed_a/b` 只表示现有动作事件按游戏顺序完成，不作为临床正确率。没有实现 80% 临床达标或自动进阶。

保存异常时停止游戏并提示重试保存，不能继续展示虚假的“已保存”。已经收集的 JPG 不因后续重试或异常被覆盖/删除。

## 客户最小验收

先分别用 A 1组、B 1组，再用 `1+1组` 验证连续模式。所有实际动作遵从现场安全要求；异常注入由旁边操作人员完成，不要求训练者边动作边操作电脑。

| 测试 | 预期游戏效果 |
| --- | --- |
| 仅组合 A | 从伸膝开始；完成设定 A 组数后直接总结，B 始终为 0 且不要求浅蹲 |
| 仅组合 B | 从站立准备开始；不要求伸膝或坐站，站回完成设定 B 组数后总结 |
| A+B 连续 | 保留原 A 后 B 顺序；A 最后一组高处拍完保持站立进入 B |
| A 正常完成 | 对焦时 0 张；放下后自动进入坐站；高处快门后 1 张双联照片 |
| 对焦后不放下 | 停在“放下小腿”，不进入坐站、不计组合照片 |
| A 多组 | 每组高处只拍一次；未坐回不能开始下一组 A |
| A 最后一组 | 仅 A 时直接总结；A+B 时保持站立进入 B，不要求多做一次坐回 |
| B 拍完继续保持浅蹲 | 只播放一次低处快门；组合照片数暂不增加 |
| B 站回 | 站回确认后增加 1 张，最后一组才进入总结 |
| 衔接等待超过 5 秒 | 只出现中性提醒，不跳过、不删除照片，可以继续 |
| 重新本组 / 调整下一组 | 当前未完成组不生成照片，已完成作品保留，事件能区分重试与主动跳过 |
| 短时断流 / 暂停 / 重标定 | 不累计、不补拍、不串接旧步骤；短时断流保持静音，恢复或继续后按提示准备 |
| 安全停止 | 不能继续原会话，已有照片保留 |
| S2 完成后返回 S1 | 原三个单动作入口仍可使用，不串接 S2 照片或次数 |

客户反馈请提供：构建版本、组数、训练动作选择、每项通过/未通过、卡住的组合/组号/步骤、当时操作、截图或录屏，以及这次原始动捕 JSONL 与 `TrainingSessions` 下完整会话文件（包括 JPG）。不要只发截图里的合计次数。

## 自动验证

`Tools/Check-Stage1.ps1` 进行 C# 编译与纯逻辑回归。Unity 菜单 `Tools → Rehab Photo Game → Run Stage 6 Regression Tests` 追加原有阶段回归、S2 入口、互斥模式、照片解码与总结关联测试。批处理日志在 `Logs/Stage6-validation.log`，渲染和测试会话在 `Logs/Stage6Review`；测试会话不是客户实际训练结果。

设备在客户现场，本地合成时序与界面测试不能替代真实四传感器验收，也不能作为临床安全或动作识别可靠性的认证。
