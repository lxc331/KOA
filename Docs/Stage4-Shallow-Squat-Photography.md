# 第4段：浅蹲摄影游戏联调说明

更新日期：2026-09-13。当前目标是打通“站稳 → 下蹲 → 保持拍照 → 站回”，待客户现场验收。

## 本轮修改边界

只调整浅蹲游戏判定、参数、反馈和诊断日志，不修改人物骨骼驱动、四元数转换、根节点补偿及传感器采样。坐姿伸膝和坐站判定保持现状；保留正式中文界面、固定取景框及 `C_低处` 图片内容向上滚动的效果。

当前放宽版不能作为“浅蹲与坐下已可靠区分”的验收依据。先站稳的前置条件仍在，但真实坐姿若被底层角度误测为站姿，游戏层不能纠正；先站稳后坐下也可能落入放宽后的目标区。动作测量由客户结合设备调稳后，再收紧规则验证动作区分。以下数值仅为软件联调参数，不是运动处方或医学安全判定。

## 新判定规则

- 每侧进度 = `max(0, 当前膝角 - 该侧站姿膝角) / minimumKneeFlexionDeg`，显示限制在 0～100%；总进度取两侧较小值。
- 默认两侧膝角各比自己的站姿参考增加至少 20°，才能进入保持。不再要求“大腿两项 + 膝盖两项”全部达标。
- 大腿屈曲量不足只提示；保持稳定性只检查双膝。大腿仍参与初始站姿/站回确认及过深上限检查。
- 普通左右幅度差异只提示，不打断保持。明显单腿动作阻止拍摄：一侧达到目标，另一侧变化小于 8°，或较小/较大膝屈曲量小于 0.20。即使不是明显单腿，两侧也仍须各自达到膝角目标。
- 过深时停止保持并清零本次保持时间，保留站姿参考。回浅后重新累计完整 2 秒，不补用过深前的时间。
- 短时断流沿用冻结逻辑；超出宽限、主动重置或重标定时清除参考，必须重新站稳。暂停/继续也重新准备。

## 状态机

| 状态 | 进入/判定条件 | 后续行为 |
| --- | --- | --- |
| `Preparing` | 开始、重置、长时断流或一轮结束；四项角度在站姿范围内并稳定 0.7 秒 | 建立左右独立站姿参考后进入 `Lowering` |
| `Lowering` | 双膝相对各自参考屈曲 | 两侧均达目标且不是明显单腿动作，进入 `Holding` |
| `Holding` | 双膝在目标范围内且稳定 | 连续有效新样本保持 2 秒拍一张，进入 `Returning`；不足目标则返回 `Lowering` |
| `TooDeep` | 下蹲/保持期间任一大腿或膝角超过上限 | 保留参考、保持时间归零；各角度回到上限减 5°以内后重新判定/保持 |
| `Returning` | 已拍摄 | 不再拍第二张；站回原参考容差内并稳定 0.6 秒，完成循环并重新准备 |

`TooDeep` 的界面显示“回浅一点”，不再退回准备并反复要求站直。未建立站姿参考时仍只提示“请先站直并站稳”，不会跳过准备。

## 客户如何调整参数

1. 在 Unity 停止播放。
2. 在 Project 中选中 `Assets/Resources/RehabPhotoGame/ShallowSquatGameTuning.asset`。
3. 在 Inspector 展开 `Settings`，按中文分组/悬浮提示修改参数并保存项目。
4. 再次播放，进入“浅蹲摄影”并开始训练。参数在运行时复制加载，播放中改资产不会立即改变本次判定；必须停止后重新播放。发布后的程序需要重新构建才能带上新参数。

优先调整“双膝主判定”中的 `Minimum Knee Flexion Deg`（最小相对膝屈曲量），每次只改一组参数。不要通过扩大超时时间掩盖断流，也不要继续要求客户蹲得更深去弥补某侧测量错误。如果停在 `Preparing`，应检查站姿角度/有效数据，降低下蹲目标不会绕过这个前置条件。

| Inspector 字段（代码名） | 默认值 | 用途 |
| --- | ---: | --- |
| `standingThighMinDeg / standingThighMaxDeg` | -20° / 25° | 站姿大腿范围 |
| `standingKneeMinDeg / standingKneeMaxDeg` | 0° / 30° | 站姿膝角范围 |
| `minimumKneeFlexionDeg` | 20° | 两侧各自必须达到的相对膝屈曲量 |
| `minimumThighFlexionDeg` | 5° | 大腿变化过小的辅助提示，不阻止拍摄 |
| `singleLegMinimumFlexionDeg` | 8° | 明显单腿的低侧变化判据 |
| `singleLegMinimumRatio` | 0.20 | 明显单侧主导的低侧/高侧比值判据 |
| `maximumShallowThighDeg / maximumShallowKneeDeg` | 80° / 100° | 绝对测量角度的过深上限，不是相对屈曲量 |
| `tooDeepRecoveryMarginDeg` | 5° | 过深后默认需大腿 ≤75°、膝角 ≤95°才恢复 |
| `maxLegProgressDifference` | 0.50 | 相对双膝屈曲量之差/目标的提示门限，未截断为百分比后再比较 |
| `maxAngleAsymmetryDeg` | 20° | 站姿确认仍要求左右对称；下蹲时仅提示相对膝屈曲量差异 |
| `stableRangeDeg` | 12° | 稳定窗口内角度最大波动；保持只查膝，准备/站回查四项 |
| `returnedToleranceDeg` | 15° | 站回时相对原站姿参考的容差 |
| `readySeconds / holdSeconds / returnSeconds` | 0.7 / 2.0 / 0.6 秒 | 准备、保持和站回计时 |
| `minimumConfirmedSamples` | 2 | 最少有效新样本数，重复旧样本不增加计时 |
| `sensorTimeoutSeconds / maxSensorSkewSeconds` | 2.2 / 2.2 秒 | 沿用传感器新鲜度与帧间时间差门限 |
| `signalGraceSeconds` | 4.0 秒 | 从检测到信号无效起计算的冻结宽限 |

无效组合会显示参数错误，不会静默拍摄。例如单腿低侧门限必须低于膝屈曲目标；膝角上限减恢复余量必须覆盖“站姿膝角最大值 + 相对目标”。当前配置校验允许的大腿/膝角上限分别不超过 90°/100°。

## 客户复测与反馈

1. 正常闭环做 3 次：等到“准备完成”，双膝屈曲后观察是否进入保持、2 秒拍照、站回后再允许下一次。取景框保持固定，只滚动图片内容。
2. 一次拍照后保持原姿势，确认不会连续拍照。界面照片数在快门时增加；日志 `repetitions` 要等站回才增加，`captureSequence` 在快门时增加，两者不必同时变化。
3. 普通左右差异：两侧都达自己的最低要求时，允许一边提示“尽量同步”一边保持；明显单腿或任一侧未达要求时不拍照。
4. 过深恢复分支：用已有过深输入/受控回放验证，进入 `TooDeep` 后参考仍在、保持归零；回到恢复范围后从零累计完整保持，不必重新建立站姿。不要为了验证软件上限要求真人刻意深蹲。
5. 未站稳就下蹲、主动重置、长时断流恢复：均不能直接接续拍照，必须先重新站稳。短时断流仍冻结进度与计时，不累计丢失时间。
6. 切换坐姿伸膝、坐站、浅蹲，确认当前模式独立计数，固定图片布局不变。本轮先确认模式互斥，不宣称真实动作已可靠区分。

客户反馈请一起提供：本次配置资产或 Inspector 截图、从站稳到站回的完整录屏、对应原始 JSONL，以及“卡在哪个提示、约第几秒、实际动作是什么”。硬件条件允许时，录屏之外补充真人同步画面，不能只凭人物模型认定真实姿势。

日志沿用 `shallow_squat_` 前缀。启动记录 `shallow_squat_game_tuning` 有效配置；快照新增 `hasStandingReference`、`leftKneeFlexion`、`rightKneeFlexion`、`coordinationWarning`，并保留原始四项测量、双侧进度、保持时间和原因。状态/原因变化时立即记录，其余约每 0.5 秒记录，便于区分准备未完成、某膝未达标、明显单腿、过深和断流。
